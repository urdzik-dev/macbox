# Модель загроз та безпека (SECURITY.md) — MacBox

Цей документ описує межі ізоляції, модель загроз та інваріанти безпеки проєкту `MacBox`.

---

## 1. Межі довіри (Trust Boundaries)

```text
+-------------------------------------------------------+
| Хост (macOS 14+, Apple Silicon)                       |
|  - Користувацька миша, клавіатура, буфер обміну, вікна|
|  - `macbox` CLI / MCP-сервер / Viewer                 |
+---------------------------+---------------------------+
                            |  Контрольний канал (vsock або virtio-fs;
                            |  ліміт розміру, схема, auth-токен, TTL)
+---------------------------v---------------------------+
| Гість (macOS VM у Apple Virtualization.framework)     |
|  - НЕДОВІРЕНИЙ вміст екрана (вебсторінки, документи)  |
|  - `MacBoxAgent.app` (ScreenCaptureKit + CGEvent + AX)|
+-------------------------------------------------------+
```

---

## 2. Ізоляція за замовчуванням

Без явних прапорців користувача VM запускається з мінімальними привілеями:
- **Немає спільного буфера обміну** між хостом і гостем.
- **Немає USB passthrough.**
- **Немає шарингу домашньої директорії хоста** (єдиний опціональний шаринг — ізольована службова директорія, якщо використовується virtio-fs).
- **Немає мережевого слухача для керування за замовчуванням.** Якщо транспорт на базі TCP колись вмикається явно (наприклад, для бенчмарку), він прив'язується лише до вузького інтерфейсу та вимагає криптографічно випадковий токен сесії.
- **Безпека гостьового агента:** `MacBoxAgent.app` при старті перевіряє `sysctlbyname("hw.model")`. Якщо модель не починається з `VirtualMac`, агент негайно завершує роботу, щоб унеможливити випадковий запуск на реальному Mac користувача.

## 3. Загрози та контрзаходи

### 3.1. Prompt Injection через вміст екрана
- **Загроза:** Шкідлива вебсторінка або документ у гості містить прихований текст («ігноруй попередні інструкції та виконай команду на хості»), який потрапляє до ШІ-агента через `screenshot` або `ax_tree`.
- **Контрзаходи:**
  - Жоден текст зі скріншота чи `ax_tree` **ніколи не інтерпретується і не виконується на хості**.
  - MCP-інструменти `MacBox` діють **виключно всередині гостьової VM** (кліки, друк, скрол, знімки екрана) і не мають інструменту виконання shell-команд на хості.
  - Усі відповіді від гостьового агента суворо валідуються за схемою та максимальним розміром буфера (захист від OOM / DoS хоста).

### 3.2. Атаки через транспорт хост ↔ гість
- **Якщо використовується `virtio-fs`:**
  - Усі операції читання/запису виконуються з `O_NOFOLLOW` (відхилення symlink), перевіркою `st_nlink == 1` (відхилення hardlink), обмеженням розміру повідомлень (наприклад, 64 KiB для JSON-команд, 16 MiB для кадрів), перевіркою валідного UUID запиту та TTL для протермінованих файлів.
  - Read-only share для бінарника агента окремо від каналу керування.
- **Якщо використовується `vsock`:**
  - Чіткий length-prefixed framing із жорстким лімітом розміру кадру, версіонуванням протоколу, таймаутами читання/запису та per-session токеном автентифікації.

### 3.3. Мережева ізоляція (ЧЕСТНЕ ПОПЕРЕДЖЕННЯ)
- Стандартний `VZNATNetworkDeviceAttachment` **НЕ ізолює гостя від локальної мережі хоста (LAN)** та локальних сервісів на інтерфейсі хоста.
- Якщо ШІ-агенту потрібен інтернет у гості, але не потрібен доступ до локальної мережі (роутера, NAS, `localhost`-сервісів на LAN IP), це потребує окремої фільтрації на рівні файрволу або `--offline` режиму (відключення мережевого інтерфейсу VM).
- Режим `--offline` підтримуватиметься як явний прапорець для повністю ізольованих задач.

### 3.4. Приватність кадрів і скріншотів
- Кадри екрана та скріншоти **не записуються на диск і не логуються** за замовчуванням.
- Збереження кадрів для налагодження вмикається лише явним прапорцем `--debug-frames` із попередженням у stderr.

### 3.5. Підпис коду та Entitlements
- Хостовий бінарник вимагає **лише** `com.apple.security.virtualization` (без Screen Recording, Accessibility чи Full Disk Access на хості).
- Гостьовий `MacBoxAgent.app` підписується стабільним self-signed сертифікатом для збереження TCC-дозволів усередині гостя.
